## 2. 봇의 빈틈 (우리가 채울 것)

1. **성과 피드백 루프가 없다.** `theme_performance(actual_return_d1/d5/d20)` 테이블은 정의만 있고 쓰는 코드가 없다. 점수가 맞는지 아무도 모른다.
2. **근거가 LLM 기억에 의존한다.** Step2b "업계에서 공급 관계가 검증된 기업" 조건은 검증 수단이 없다. 우리는 **위키 본문**이 있다.
3. **테마 DB가 둘이다.** 봇의 `theme_stocks`(277 테마·4,905행, 2,274행이 '기타') vs 앤트위키 252 테마·2,929 엣지. 봇 분류와 사이트 분류가 어긋나면 사용자가 링크를 따라가도 다른 그림을 본다.
4. **문서 드리프트.** PIPELINE_DETAIL은 6지표 가중합(단기/장기 60점 컷)을 설명하지만 코드는 tier 체계로 바뀌어 있다.
5. 출력이 텔레그램 3단 내러티브 1종이라 "왜 이 종목인가"를 길게 설득하지 못한다.

## 3. 고도화 아이디어 (우선순위순)

### A. 위키 역색인으로 공급관계를 "검증"한다 (KB 전용, 가장 차별화)
- 2,651개 위키 본문에서 **기업명 언급 역색인**을 만든다: `mention_index[회사명] → [그 회사를 본문에 언급한 위키 종목, 문장]`.
  예) "SK하이닉스" → 한미반도체 위키 "SK하이닉스와의 깊은 협력 관계…", 한전KPS 위키에는 없음.
- 기사 주체 기업이 나오면 이 역색인이 **tier 1/2 후보와 근거 문장을 동시에** 준다. 봇이 LLM 기억으로 하던 "알려진 납품사"를 위키 문장으로 대체 → `kb_evidence`가 항상 채워짐.
- 구현: `kb/build_kb.py`에 `index/mention_index.json` 생성 단계 추가(종목명 2,670개를 모든 섹션 텍스트에서 검색, 자기 자신 제외). 1회 수 분.

### B. specific_segment → 테마 라우팅
- 분석 1단계에서 specific_segment를 뽑고, `theme_aliases`로 **테마 slug에 매핑**한다(매핑 실패 시 산업 지도의 밸류체인 라벨과 매칭).
- 후보 풀 = 그 테마의 구성종목(tier 2·3) + 역색인 결과(tier 1). 언급 종목의 "모든 테마"를 펼치던 현재 방식(삼성전자→CXL·DRAM·HBM·IDM·NAND·파운드리 전부)을 끊는다.

### C. 성과 추적과 점수 보정
- 발행한 글의 수혜주를 `data/track/{date}.jsonl`에 기록하고, `GET /api/v1/market/stocks?codes=`로 D+1/D+5/D+20 수익률을 채운다(봇이 비워둔 theme_performance를 우리가 구현).
- 월 1회 "큐레이터 적중률" 글을 피드에 올리면 신뢰 자산이 된다. 점수 가중치·tier 컷을 데이터로 조정.

### D. 봇 ↔ 큐레이터 역할 분담 (같은 뉴스, 다른 상품)
- 봇 = 속보형(5분 주기, 3단 내러티브, 텔레그램). 큐레이터 = 하루 3~5건 엄선, 위키 근거 장문, 사이트 피드.
- 봇의 `sent_analysis_log`(Supabase)를 읽어 **봇이 이미 다룬 기사 중 점수 상위**를 큐레이터 후보로 쓰면 수집·프리스크린 비용이 0이 된다. 반대로 큐레이터가 쓴 글 링크를 봇 메시지에 "자세히 보기"로 붙일 수 있다.

### E. 테마 단일화 제안 (크로스 프로젝트)
- 봇의 `theme_matcher`가 Supabase `theme_stocks` 대신 `api.ant.wiki/theme-page/*`를 읽게 바꾸면 사이트와 봇의 분류가 일치한다. 자동발굴 결과는 앤트위키 `theme-page/edit-requests`(편집 요청 API)로 보내 사람이 승인하는 흐름으로.

### F. 피드 포맷 실험
- 피드 v2 계약의 `poll`을 활용: "이 뉴스의 진짜 수혜주는?" 2~4지선다(우리 후보 중) → 반응 데이터가 C의 보정 입력이 된다.
- 글 말미에 "앤트위키 커뮤니티는 이렇게 본다"(위키 bullish/bearish 내러티브 1줄씩) 섹션 고정 → 사이트 내부 콘텐츠로 체류 유도.

### G. 0토큰 필터 강화
- 봇 프리스크린의 탈락 기준을 정규식으로 이식: `(의원|장관|시장|지사).*(강조|촉구|제언|발의)`, `(수상|선정|표창)`, `(상생|CSR|후원)`, `(캐시백|이벤트|프로모션)`, `(재건축|재개발).*(수주|시공)`, `(IND|INN|신청|접수) 완료` 등. 채택 39건 중 카카오프렌즈 런·매일유업 표창·DN오토모티브 수사 같은 건이 걸러진다.

## 4. 바로 할 수 있는 순서
1. G(정규식 필터) + B(specific_segment 라우팅) → 프롬프트·collect 수정만으로 가능, 반나일.

4. D·E → 봇 저장소 변경이 필요하므로 봇 담당과 합의 후.
